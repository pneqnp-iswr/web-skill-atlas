# Frontend gaps after deep pass — 2026-08-27

## High-priority published-skill gaps

- CSS engineering remains far behind framework coverage: specificity, cascade layers, stacking contexts, overflow, sticky positioning, custom properties, grid/flex debugging, container-query procedures.
- Browser-platform skills remain sparse: DOM events, observers, storage, IndexedDB, Workers, Web Components, Visual Viewport, File/Drag-and-Drop APIs.
- Mobile browser quirks and Safari-specific implementation procedures are still weak.
- Framework breadth is uneven. React/Next/Vue/Svelte/TanStack are relatively strong; Solid, Qwik, Preact, Lit/Web Components, Alpine.js, HTMX, and legacy modernization are underrepresented by published skills.
- Forms are still thin outside framework/library-specific integrations. Native forms, file upload, async validation, multistep forms, and resilient error-state procedures need stronger published sources.
- Real-time UI, WebSocket/EventSource lifecycle, reconnect/order/conflict workflows are weak.
- Source maps, chunk-load failures, stale-deployment recovery, frontend observability, browser memory leaks, and DevTools workflows need additional canonical reusable procedures.

## Research limitations

- skills.sh was treated as discovery, never as proof of canonical provenance.
- Social-video platforms do not expose code-level, stable, exhaustive skill indexes comparable to GitHub; they were not treated as authoritative corpora.
- Search-engine and GitHub indexing are incomplete, so this pass improves saturation but does not claim literal whole-internet exhaustiveness.
- Documentation-derived opportunities are intentionally segregated from the published dataset.
